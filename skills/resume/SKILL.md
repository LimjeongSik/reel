# 이력서 원고 → work/resume.md

먼저 이 스킬 폴더 기준 `../../shared/writing-rules.md`를 읽는다. 특히 3장(같은 이야기를 두 번 쓰지 않는다)과
4장(고르는 문서다)이 이 스킬의 핵심이다.

입력: `work/profile.md`, `work/cases/*.md`. 없으면 scout → clips를 먼저 실행한다.

**사용자의 기존 이력서를 먼저 읽는다**(예: `~/Desktop/Portfolio/resume/resume.md`, `resume/content.js` — 위치를 모르면 묻는다).
- 소속 · 직함 · 재직 기간은 거기서 가져온다(저장소로는 알 수 없다). 가져온 사실은 머리말에 출처를 적는다
- 문체 · 항목 순서(개요 → 배경 → 사례)와 "경력" 섹션에 이미 쓴 줄을 맞춘다 — 2장 "경력 항목에 넣을 줄"이 기존 줄과 겹치지 않게
- 다른 프로젝트에 이미 같은 종류의 사례가 있으면(cases/ 머리의 "겹침") 1장 짧은 버전에서는 빼고, 3장에는 남기되 겹침을 주석으로 표시한다
- 같은 수치를 다른 프로젝트에서 이미 썼으면(예: 테스트 수) 이 원고에서는 다른 수치를 고른다
여기서는 새 사실을 만들지 않는다. 사례 파일에 없는 수치나 주장이 필요해 보이면 `<!-- TODO -->`로 남기고 사용자에게 묻는다.

## 왜 여러 길이로 쓰나

지원서마다 칸이 다르다. 이력서 PDF의 프로젝트 칸은 3줄, 경력기술서는 한 쪽, 자기소개 칸은 500자 제한이다.
같은 프로젝트를 매번 다시 줄이게 하지 않으려고, **길이별로 미리 잘라 둔 원고**를 한 파일에 담는다.
사용자는 필요한 칸에 맞는 덩어리를 골라 복사한다.

## 출력 형식 — work/resume.md

```markdown
# <프로젝트명> — 이력서 원고

> 근거: work/profile.md · work/cases/. 수치는 저장소에 기록된 실측값만 썼습니다.
> `<!-- TODO -->`는 저장소에 정보가 없어 직접 채워야 하는 곳입니다.

## 1. 이력서 프로젝트 칸 (짧은 버전)

**<프로젝트명>** · <역할> · <YYYY.MM — YYYY.MM 또는 현재>
<한 줄 소개: 무엇을 하는 서비스인가>

- <가장 강한 사례의 한 줄 요약>
- <두 번째>
- <세 번째>

기술: <반복해서 쓴 핵심 기술만, 5~8개>

## 2. 경력 항목에 넣을 줄

<회사 경력 아래에 붙일 2~3 bullet. 프로젝트 칸과 겹치지 않게 조직 안의 역할과 영향 — 설계 범위, 리드 · 리뷰,
출시 · 운영, 도입 현황 — 위주로.>

## 3. 경력기술서 상세

- **기간** … · **역할** … · **팀** … · **플랫폼** …
- **성과** 출시 · 운영 · 규모 등 사실만
- **링크** …
- **기술** …

**배경.** 이 서비스가 왜 까다로웠나. 사용자 맥락에서 기술 요구가 나온 과정 2~4문장.

**① <사례 제목>**

- 문제: …
- 해결: …
- 전 → 후 (`해시`): 핵심 변화 한두 줄(코드 이름은 백틱으로)
- 결과: …

(사례 3~5개. cases/ 순서 그대로)

**일하는 방식.** 사례들에서 공통으로 드러나는 습관 한 문단(근거가 된 사례 번호를 괄호로).

## 4. 자기소개에 끼울 문장

- **한 줄 (40자 안팎)**: …
- **세 줄 (150자 안팎)**: …
- **문단 (약 300자)**: 이 프로젝트에서 가장 강한 사례 하나를 문제 → 해결 → 결과로.

## 5. 핵심 역량 bullet

역량 이름(예: "라이브러리로 해결되지 않으면 네이티브까지 다룹니다") 아래 근거 bullet 1~2개. 2~4개 역량.

## 6. 면접 예상 질문

| 질문 | 답의 실마리 | 근거 |
|---|---|---|

## 확인 필요
- …
```

## 쓰는 법

- 다 쓴 뒤 `../../shared/writing-rules.md` 5-1의 표로 문장을 한 번 더 고친다. 번역투 · 명사 나열 · 커밋 메시지 말투가 남아 있지 않게.
- 쓰기 전 `check`, 쓴 뒤 `record` — `../../shared/work-layout.md`의 덮어쓰기 규칙. 사용자가 고친 원고면 `*.new.md`에 쓴다.
- 마지막에 `../../shared/scripts/check-work.sh work`를 돌려 오류(✗)를 고친다.

- 1장 bullet은 "행동 동사 + 무엇을 + 어떻게(기술) + 결과"를 한 줄에. 결과가 수치면 수치를, 없으면 확인 수준을
  ("양 플랫폼 실기기 확인"). 한 줄이 두 줄을 넘으면 너무 긴 것이다.
- 1장과 3장의 문장을 똑같이 복사하지 않는다. 1장은 결과 중심, 3장은 과정 중심이다.
- 사례 순서는 cases/ 번호 그대로. 순서를 바꾸고 싶으면 cases/ 파일 번호부터 바꾼다(포트폴리오 · 이미지 목록의 ①②가 어긋나지 않게).
- 2장은 프로젝트를 회사 경력 안에서 쓸 때만 의미가 있다. 개인 · 외주 프로젝트면 "해당 없음"이라고 쓴다.
- 기간 형식은 `YYYY.MM — YYYY.MM` / `YYYY.MM — 현재`. 사용자의 이력서 템플릿이 이 형식으로 기간을 계산하는 경우가 많다.
- 다 쓰고 나면 사용자에게 1장(짧은 버전)을 보여 주고 "확인 필요" 목록을 함께 묻는다.
